# dryfire threat model

dryfire reads the most sensitive record on a developer's machine (every command an agent ran, with whatever secrets
were in it) and, when asked, runs other people's code against it. This file says what it protects, how, and where
each protection stops.

## Assets

1. **Transcript content**: commands, file paths, tokens and other secrets that appear in past tool calls.
2. **The user's files and accounts**: anything a hook under test could read, change or send.
3. **The approval decision**: which hook commands may run.

## Who can influence dryfire

| Source | Trusted? | Examples |
|---|---|---|
| The user at the keyboard | yes | approves hooks, edits their own settings |
| The agent (Claude) | partly | runs `detect`, `scan`, `replay`; may have been steered by injected text |
| A project's files | no | `.dryfire/config.json`, `.claude/settings.json` in a cloned repository |
| Transcript text | no | commands and outputs written by earlier sessions, tools and web pages |
| A hook under test | no | any program the user points dryfire at |

## Threats and controls

| Threat | Control | Limit |
|---|---|---|
| Transcript content leaves the machine | The package has no network code; `tests/test_static.py` fails on any import of `socket`, `ssl`, `urllib`, `http`, `requests`, `asyncio` and similar, and on `__import__`/`importlib`. Hooks under test have network denied on macOS | On Linux a hook under test can reach the network (environment sandbox only) |
| Secrets in replayed commands reach a report, the terminal or the model | Every string a report prints goes through `redact.clean()`: the vendored token patterns, values named like secrets (`TOKEN=`, `export DEPLOY_TOKEN value`, `--password`, `Authorization:` headers, client password flags such as `mysql -p`, `sshpass -p`, `keytool -storepass`, `htpasswd -b`/`-nb`, `docker login -p`, `openssl -passout`/`-passin`/`-k` and `curl -u`, every such flag on the line, attached, clustered, `=` and quoted values included (a value is one whole shell word in any quoting: plain, quoted and escaped parts joined, `$'...'`, `$"..."`, `"a\"b"`, `a\ b`, a reference joined to text such as `$X-S`, a quote left open to the end of the line, a backslash-newline; a `curl -u` value is masked after its first `:` and only a value that is one reference and nothing else, such as `$P`, `"${P}"` or `$(cat f)`, or `` `cat f` `` is kept; a default `${P:-S}`, text joined after a closed `$(...)` or backticks, an unclosed `$(` or backtick, and a substitution that may print its own words count as text: a substitution is kept only when it reads a file (`$(< f)`) or its commands, joined by `|` or `&`, are each a known fetcher written plainly (`cat`, `head`, `tail`, `base64`, `op`, `gh`, `pass`, `security`, `aws`, `gcloud`, `az`, `vault`, `sops`, `gpg`, `kubectl`, `doppler`, `bw`, `lpass`, `secret-tool`, `heroku`, `jq`, `yq`, `pbpaste`) whose arguments hold no inner quote (a whole quoted option value such as `jsonpath='{.data.token}'` and an error redirect `2>/dev/null` or `2>&1` are fine), no `--`, `run` or `exec`, no word that stores or takes a secret, alone or as a part split at `-` or `:` (`unlock`, `set`, `create`, `edit`, `put`, `write`, `login`, `encrypt`, `add`, `patch`, `update`, `lookup`, `import`, `store`, `insert`: `put-parameter`, `config:set`, `-X PUT`), a part split at `=` too (`--method=PUT`), no `--passphrase`, `--from-literal`, `--body`, `--password`, `--secret`, `--value`, `--field`, `--raw-field`, `-f` or `-F`, and for `gh api` (the word quoted or not) no `-f`, `-F`, `-X` or `-H` in any short cluster (`-fk=v`, `-XPUT`, `-Hk:v`) and no `--method`, `--input` or `--header`, nothing a named-value pattern would mask, and for `jq`/`yq` no `-n` or `--arg`; any other command (`echo` in any spelling, `date +S`, `perl -e`, `timeout ... echo`) makes it text; more than one command (`;`, `&&`, `||`, a newline), a heredoc or here-string, or a nested substitution is text too; values named like secrets read the same whole word; a value the 1024-character reading bound cuts is masked to the end of its line), while port maps and `env:`/`file:` pointers are kept, and passwords in URLs even with an empty user name), long random-looking values, the user's `redact_patterns`, home path as `~`, control characters removed, length capped. JSON and Markdown both. `approve --list`, `scan`, `detect` and config error messages mask too. dryfire keeps no cache of command text. Masking runs in linear time on hostile input; a project's `redact_patterns` with a backtracking shape or in verbose mode or with a comment group (`(?x)`, `(?#...)`, which can hide that shape) is refused, and custom patterns only see the text a report will show | Masking is pattern-based: a secret with no recognisable shape and no telling name can get through, and so can one a fetcher is told to print through an option with no inner quote (`aws --query S`, `jq .S`), or one given to a fetcher subcommand outside the store words above as a plain argument. It is tuned to over-mask. A slow pattern in your own config is trusted and can still be slow |
| Prompt injection in transcripts | Transcript text is parsed as JSON and never executed or formatted into a shell command; it reaches a hook only as JSON on stdin. Reports start with a notice that their content is data, samples are fenced with a fence longer than any backtick run inside, and headings and table cells allow only a safe character set. The skills tell the model to quote, never follow, instructions in a report | A model can still be influenced by text it reads; the controls make that text clearly data, they cannot make the model immune |
| A hook under test damages files or exfiltrates data | Runs only after approval of that exact command, arguments and plugin folder, and the content of every file the command names (up to 256 MB in all; past that the hook cannot be approved). Each call gets a fresh private temp folder (HOME, project, data, TMPDIR), removed afterwards; the environment is rebuilt from `PATH` and locale only; on macOS `sandbox-exec` denies network, writes outside the temp folder, reads in the home folder except the hook's own files, its interpreter and `allow_read` paths, and the system services that would act for it (preferences, pasteboard, keychain, Launch Services, Spotlight); time limit with a kill of the whole process group; processes that left the group are found by an environment marker and killed when the hook's replay ends; output capped | On Linux there is no OS sandbox in v0.1: a hook runs with your user's file access (but a temp HOME and clean environment). `sandbox: required` refuses instead. Paths outside the home folder stay readable on macOS. A file named only through something worked out when the hook runs (`$(...)`, a variable set outside the command) is not part of its approval (a variable set earlier in the command is followed, `cd "$D"` and `cd -P "$D"` included (but not `cd` into a loop variable), as is a script read from input after a `cd` (`bash < g.sh`, `bash <> g.sh`), as are each value of `for D in ...` and each combination of nested loops (up to 64 per word), the default of `${D:-/dir}` (also when D is empty), and a line ending in a comment with an odd quote), and files the command only writes to through `>`, `>>`, `>|`, `&>`, `&>>` or `>&` are left out so a log does not undo the approval (all are kept when the line also has a quoted or escaped `>`, which reads the same once unquoted). A process that leaves its group and also clears its environment can outlive the run (on macOS still inside the sandbox). Files a hook's script imports are not part of its approval |
| A cloned repository proposes a hook or loosens settings | A project's `.dryfire/config.json` can only tighten safety keys; its `hooks` and `allow_read` are inert until the user approves them for that project; it cannot add transcript folders | Approval is by fingerprint: a user who approves without reading the command is not protected |
| A run flag loosens settings | Run flags follow the project rule: tighten only | |
| The agent approves a hook for itself | dryfire's own PreToolUse hook (`selfguard`) asks the user before any `approve`, `set`, `unset`, `init` or settings `approve` command, and denies them in unattended modes (`dontAsk`, `bypassPermissions`). It also asks when dryfire's subcommand is only known when the line runs (`$A`, `$(...)`, `xargs {}`), when a command that runs dryfire sets or may set `HOME` or `CLAUDE_PLUGIN_DATA` in any way other than reading them (which decide where approvals are read from), and reads commands started through launchers such as `arch`, `script -qc`, `flock --command=`, `env -S` (read from the raw line, nested lines too), `taskpolicy`, `parallel` and `find -exec`, and `python3 -m dryfire.main`, `-m cli` or `-m cfgtool` in any option form. A line that names dryfire's scripts or modules (or is run from its folder) and sets or may set either variable asks even when part of the line cannot be parsed, or when the line feeds text into another command (a pipe into one, `xargs`, a heredoc or here-string, a substitution), since the run may be that text (`echo 'HOME=... cli.py scan' | sh`); a commit message's quoted heredoc is left out of this. A run whose subcommand is missing from the line asks too (only `--help` and `--version` pass), and `HOME` set through a name built from quotes or backslashes (`HO''ME=...`, `H\OME=...`) or split by a backslash-newline counts as setting it. So does anything on a line that runs dryfire that could build a name once the line runs: any expansion other than `$HOME`, `$CLAUDE_PLUGIN_ROOT` and `$CLAUDE_PLUGIN_DATA` (plain, or in `${...}` with nothing else), a brace list or range, a glob (`*`, `?`, `[`, or a zsh qualifier glued to a word such as `/(e:...:)`), text the shell reads again (`source`, `.`, `eval`, `trap`, `emulate`, `printf`), `declare`, `typeset` or `local` (whose `-u` and `-l` change a value's case and `-i` evaluates it), arithmetic (`((`, `let`), which reads a variable's value as an expression, and the commands that give a variable a value from outside the line (`read`, `mapfile`, `readarray`, `select`, `vared`, `sysread`; `echo 0=EMOH | rev | (read n; (( n )))` sets `HOME`), each looked for both as written and with quotes, backslashes and backslash-newlines taken out (`e''val`, `trap 'HO\<newline>ME=...'`). The ways a shell can build a name from these (`HO${Z}ME`, `{HO,}ME`, `HOM?`, `$'HO\x4dE'`, `(( ${V}ME = 0 ))`, `$C ${V^^}`, text decoded and sourced) have no end, so dryfire asks on all of them; dryfire's own commands name only its folders. An `env` spelled through quotes or expansions (`$'env' -S ...`) is read as `env`. Commands that only read or record text (`grep`, `cat`, `echo`, and `git commit`, `log`, `show`, `diff` and similar, also after `git -C <folder>`) are not taken as runs, even when they name a script as a path (`git log -- cli.py`), but only on a plain line: one where every command starts with `echo`, `pwd`, `true`, `false`, `cd`, `pushd`, `popd`, a text command that is not a builtin, or a command named by a bare word that is not a shell builtin or reserved word (`make`, `tee`), and where no `${...}` runs code (bash's `${ cmd; }` and `${v@P}`, zsh's `${(e)...}`, inside double quotes too, which also count as feeding text). Only a builtin or reserved word (the fixed sets of bash and zsh: `eval`, `source`, `alias`, `hash`, `read`, `noglob`, `repeat`, `typeset -f`, `printf -v` with the `-v` quoted or not, `test -v 'a[...]'`...), an assignment (`PATH=...`, `BASH_CMDS[cat]=...`), a group, subshell, function or substitution, or a command word that is quoted, holds an expansion or is a path (`d/cat`) can change what a command name runs, so any of them makes every part of the line read as a run (`git() { shift; "$@"; }; git log ... cli.py approve`); a `case` statement is not plain either, so a harmless one asks. A commit message written as `"$(cat <<'EOF' ... EOF)"` with a quoted heredoc marker is text, since nothing in it expands, when the `$(` stands outside single quotes and comments, the rest of the line is plain, and the heredoc is a word of a text command whose output goes only to text commands (`| tail` passes; `echo "$(cat <<'EOF' ...)" | sh`, `sh -c`, `bash <<<` and `python3 -c` are read), no body line starts with the marker, and nothing follows the marker line inside the `$(...)`. A line that feeds text into another command (a pipe out of a command that is not text-only, `xargs`, a heredoc or here-string, `$(...)`, `<(...)`, text stored by `printf -v`, text sent to a `coproc`, `eval`, `trap`, `source`, `let` or `.` as a word of any command other than a text command or a program named by a bare word (`2>/dev/null eval`, `time -p eval`, `x=1 . f`; `echo let`, `grep -c eval` and `make eval` only name them), in such a command any word spelled through quotes, a backslash or an expansion, which may be `eval` itself (`$E`, `\eval`, `e''val`), a `-c` or `-S` option whose next word holds a `$` or a backtick anywhere, single quotes included (`x='...'; sh -c "$x"`, `bash -c "H""$x"`, `sh -c 'eval "$0"' "$x"`; `git log -S "approve"` passes), arithmetic (`((`, `let`, `[[`), whose array subscripts run `$(...)`, or any `${...}` other than a plain `${NAME}` outside single quotes) and sets or may set `HOME` or `CLAUDE_PLUGIN_DATA` asks when it names dryfire's scripts, modules or plugin folder. A line that names dryfire's scripts or modules and writes `HOME` or `CLAUDE_PLUGIN_DATA` anywhere other than as a plain read, in quotes too, asks unless it is plain and every part is a text command, since a command can read a value as words to run or names to set (`x='HOME=... scan'; bash -ce "$x"`, `sh -c -- "$x"`, `env $x`, `$x`, `perl -e "system('$x')"`); `grep HOME cli.py | wc -l` passes, `sed -n /HOME/p cli.py` asks. A comment, and a quote inside one or inside `$'...'`, never hides a `|` or `;`, a backslash at the end of a comment does not join the next line, and a `#` after an escaped character or after a `(` glued to a word starts no comment (zsh's `/(#i)x` glob flag, `echo x=(#i)y`), or after a `(` that follows a word and a blank (zsh's `ls (#i)x`), except after `NAME=(` at the start of a command, which opens an array (`a=(# x` is a comment); the command parser follows the same rule, so `ls /(#i)x; rm -rf <data folder>` is denied. Because an array also opens after an assignment, `{`, `then`, `declare` or `export`, no one reading is safe: any `#` right after a `(` outside quotes (not `$(#`, `<(#`, `>(#`) on a line that names dryfire, `.claude`, its plugin folders or scripts, or that runs from inside dryfire's folders, asks, heredoc bodies included (a commit message citing `(#42)` through `git commit -F - <<'EOF'` near dryfire asks); a pipe into text commands only (`grep ... | head`) feeds nothing, and a `|`, `;` or `&` inside quotes or part of a redirect (`2>&1 | sh`, `>|`) does not end a command; `find`, `rg` (`--pre`) and other `git` commands (`git grep -O` runs a pager command) can run a command line and are always read. A line that names dryfire's scripts or modules and holds a changing word (`approve`, `set`, `unset`, `init`) that no run it could follow accounts for (words fed in by `xargs`, a copy of the scripts) is asked about too. A command longer than 32,768 characters is asked about without being read, so the check always ends well inside the hook's time limit. Writes and edits into dryfire's data folder or plugin folder are denied, including through shell redirection, `cp`, `mv`, `tee`, `sed -i` and similar | **A speed bump, not a wall.** An agent with an unrestricted shell can reach the same files in ways no command parser sees, for example by writing a script first and running it, or by importing dryfire's Python modules directly, or by a variable set in an earlier command whose value is later evaluated as arithmetic (`(( n ))` after `n='HOME=0'` in an earlier call), or by a `cat` function or `PATH` set in an earlier command of the session, or by writing into the data folder through a name the write check cannot see as a path (`dry$Z`, `dry*`, `dryf?re`), a symbolic link made on the same line or `..` after a link (the write check resolves paths lexically before following links that already exist). The real boundary is the permission system of Claude Code and the user reading what they approve. Because any expansion or arithmetic asks, a harmless line that also runs dryfire asks too (`source "$VIRTUAL_ENV/bin/activate" && ... scan`, `(( i++ )); ... scan`, or a commit message holding the word `local`). Code that a shell or Python loads from a file (`BASH_ENV`, `ZDOTDIR`, `--rcfile`, `mapfile -C`, `PYTHONPATH`) is not read. A command of the same name written into a folder on `PATH` (on the same line or earlier) is not seen. A name of `HOME` built when the line runs and handed to a shell through a variable in a form not listed above (`x='HO$Z' ...; bash -ce "$x"`) is not seen. Text fed to a shell that names dryfire's scripts only in disguise (`cl""i.py`, `dryf*`, an octal escape, or text rewritten by `tr` or `sed`) is not traced. |
| Symlinks and path tricks in transcript folders | Folders are walked without following links; each file's real path must stay inside its root; only `.jsonl` is read; files are opened read-only | |
| `--out` overwrites dryfire's own files or an existing report | Refused inside the data and plugin folders (symlinks resolved); an existing file needs `--force` | |
| Huge or hostile transcript lines | Lines are parsed one at a time; oversized tool inputs are skipped and counted; a partial last line (a file still being written) is skipped and counted; rule-pack regexes see capped input; with hooks, only the inputs of the calls replayed are held in memory | A pathological regex in a user's own rule pack can still be slow |
| A broken or malicious rule file | Rule files are data: JSON or a strict YAML subset, never executed; invalid rules are reported and skipped | |

## Out of scope

- Protecting transcripts from other programs running as the same user: they can read `~/.claude/projects` anyway.
- A hook the user approves that is itself malicious and finds a way out of the macOS sandbox.
- Making a guard's live behaviour match the replay; see [docs/limits.md](docs/limits.md).
